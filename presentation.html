Approach and Design Decisions

🔌

Ports & adapters

  • Generic IMAP listener and SMTP sender
  • Listener yields raw bytes; sender just delivers
  • All UARB logic lives in a reader and a responder
  • Either transport can be replaced independently
🧩

Injection & abstraction

  • Clients injected, never built implicitly
  • Templated Scraper ABC with an abstract scrape method
  • ReplySender protocol and LlmClient ABC
  • Concrete OpenCode provider for the LLM
🛡️

Untrusted input

  • Email bodies and scraped titles are data, never instructions
  • Wrapped in an untrusted block; control chars and delimiters stripped; length-capped
  • Matter number validated against a fixed pattern
  • Document types validated against an allow-list
🚦

Fail safe

  • Inputs validated before any work begins
  • Timeouts on browser, LLM, and SMTP calls
  • Bounded retries and capped reconnect backoff
  • Watchdog restarts on hang; SIGTERM exits cleanly (0)
♻️

Self-healing listener

  • Holds an IMAP IDLE session, re-issued in short slices for watchdog beats
  • On socket error: disconnect, then reconnect with exponential backoff
  • Force-closes the socket if logout fails
  • A failure handling one message is skipped, not fatal
🛠️

Operations

  • Hosted on Oracle Cloud free tier with limited resources
  • Hardened systemd unit: notify + watchdog, memory caps
  • Secrets only in mode-600 .env, validated at startup, never logged

What I learned

  • Browser automation with Playwright. My first time scraping a real web app: navigating a virtualized results grid, driving document downloads, and handling flaky UI timing.
  • Designing testable, organized systems quickly. A layered architecture with ports and adapters, dependency injection, and clean abstractions kept the project easy to reason about and extend.
  • Building fast with AI. Using AI as a pairing partner to plan, implement, debug, and refine an entire pipeline end to end in a short time.
  • Running a service unattended. Reconnects, watchdogs, timeouts, and clean shutdowns matter as much as the happy path.
  • Treating model I/O as untrusted. When an LLM processes external input, prompt guards and strict output validation are essential.
